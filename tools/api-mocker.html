How to use the aPI Response Mocker & Tester

      
  1. Mock data: list field names and types (string, number, boolean, email, date, uuid, name), set a count, and generate a ready-to-use JSON array for tests or UI prototyping.
  2. Request tester: enter a method and URL, optional headers and a JSON body, then Send to see the real response status, headers and body.
  3. Use “Copy as cURL” to turn your request into a command-line cURL call for sharing with teammates or pasting into a README.
  4. If a live request fails immediately, it's almost always the target server's CORS policy blocking cross-origin browser requests — test from your backend or a tool like Postman instead for CORS-restricted APIs.

      
Frequently asked questions

      
Why did my request fail with a network error?
Browsers enforce CORS (Cross-Origin Resource Sharing): a server must explicitly allow requests from other origins. If the API you're testing doesn't send the right Access-Control-Allow-Origin header, the browser blocks the response — this is a server-side restriction, not a bug in this tool.
Is the mock data realistic enough for demos?
It generates plausible values (names, emails, dates, UUIDs, numbers) per field type, good for prototyping UIs or seeding test databases, though it's randomly generated and not drawn from real-world datasets.
Does this tool store or proxy my requests?
No — requests are sent directly from your browser to the target URL using fetch(); nothing passes through a DevToolbox server.
Can I test a locally running Spring Boot API?
Yes, as long as it's reachable from your browser (e.g. http://localhost:8080/...) and either has permissive CORS configured or you're testing same-origin.
