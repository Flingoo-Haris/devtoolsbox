How to use the jWT Decoder

      
  1. Paste a JSON Web Token (the three dot-separated Base64URL segments) into the box.
  2. Click “Decode token” to see the header and payload as formatted JSON, plus a plain-English claims summary.
  3. Check the status line to see if the token's exp claim has already passed.
  4. The raw signature segment is shown for reference, but it is never verified — verification needs the issuer's secret or public key.

      
Frequently asked questions

      
Does this tool verify the JWT signature?
No, by design. Verifying a signature requires the secret (HMAC) or public key (RSA/EC) used to sign it, and that key should never be typed into a third-party website. This tool only decodes the header and payload, which are just Base64URL — not encrypted.
Is my token sent to a server?
No. Decoding uses your browser's built-in atob and JSON parsing — the token never leaves your machine or hits a network request.
Why do I see garbled characters in the payload?
That usually means the string isn't valid Base64URL, or you've pasted only part of the token. Make sure all three segments, separated by two dots, are included.
What's the difference between exp, iat and nbf?
“iat” is when the token was issued, “nbf” (not before) is the earliest it's valid, and “exp” is when it expires — all expressed as Unix timestamps (seconds since 1970).
